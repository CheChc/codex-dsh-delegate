# 自包含任务模板

以下路径、接口、命令与输出均为示例，交付前必须替换为目标仓库中真实使用的路径、接口与可运行的命令；新增文件应使用计划创建且不冲突的路径。不要把占位符原样交给工具，也不要假定示例命令在项目中已经存在。

新实现以接口、行为、边界和可观察验收为主，不必提供逐行代码；完整原文/替换文只用于确定性的精确修补。每份委托最多写入 5 个文件，读取范围可以更宽，但要在“涉及文件”中说明。v2 从工具返回的 JSON 中读取真实 session_id，completed 仍需主代理独立复验。

## 新增模块或 CLI

示例：为项目增加一个只读的本地链接检查入口。接口、输出和异常边界已经确定，内部函数拆分与具体写法由 dsh 决定。

```text
## 目标
新增只读链接检查 CLI，能报告指定目录下 Markdown 中的失效本地链接；正常、发现问题、输入错误或扫描不完整时的退出码符合约定。

## 涉及文件
tools/check_links.py（新增）
tests/test_check_links.py（新增）
docs/check-links.md（新增，简短用法说明）

## 具体做法
实现入口 python3 tools/check_links.py <root> [--json]。
输入：一个已存在目录；递归扫描其中的 *.md，跳过 http(s)、mailto 和纯锚点链接；相对路径按所在文件解析。
输出：默认每行 相对路径:行号: target；--json 输出 {"checked": 整数, "broken": [{"path": 相对路径, "line": 整数, "target": 字符串}]}。
异常边界：目录不存在或不是目录，向 stderr 输出一行说明并退出 2；存在失效链接，列出后退出 1；全部可解析退出 0；单文件读取失败写入 stderr，继续处理其余文件，但最终退出 2，不把不完整扫描报告为通过。
只使用 Python 标准库，不新增依赖；不修改被扫描文件；测试样例用临时目录构造，不新增 fixture 文件；内部函数拆分和命名由你决定。

## 验收
运行 python3 -m unittest tests.test_check_links -v，覆盖全部通过、发现失效链接、目录不存在三种情况（示例命令，按项目真实测试入口替换）。
在临时样例目录上运行 CLI，核对退出码以及上述文本/JSON 结构；报告实际命令、退出码和结果摘要。

## 禁止
不修改被扫描目录中的文件；不增加联网检查、自动修复或计划外参数；不新增依赖；不改其他文件；不提交、不推送。
```

## 整理文档或发布说明

示例：Codex 已核实来源并定稿要点，dsh 只按固定结构整理，不自行补充事实或作判断。

```text
## 目标
把本批已核实的变更来源整理成统一结构的发布说明，只做归并、排序和格式化，不新增事实或结论。

## 涉及文件
docs/CHANGELOG.md（只替换 <!-- release: vX.Y --> 与 <!-- /release --> 之间的内容）
docs/releases/vX.Y.md（新增）
（只读来源：docs/changes/ 下的本批文件，以及任务附带的已核实来源清单。）

## 具体做法
输入：来源清单（表格或等价的逐项列表），每项给出文件路径或链接、变更类型、影响范围、是否破坏兼容；这些信息已由 Codex 核实，不重新研究。
输出：四列表格，表头依次为 类型、影响、说明、来源；类型仅用 Added、Changed、Fixed、Removed；按类型分组，组内按影响从大到小；保留文档原有标题层级和链接写法。
来源缺失、类型不在枚举内，或同一变更出现矛盾描述时，记录位置并停止该条，不猜测、不合并、不补写；不写入清单之外的内容。
不改写既有条目，不调整无关段落，版本号和日期只使用任务给出的值。

## 验收
运行项目已有的文档检查或链接检查命令；若项目没有对应命令，明确说明并改用只读检查（项目有 Git 时用 git diff --check，并按来源清单逐项核对链接目标是否存在）。
核对条目数与来源清单一致、四列齐全、无清单外事实、标记区间外无差异；报告文件、条目数、实际命令与真实输出。

## 禁止
不新增或推测变更事实；不修改来源文件；不自行改动版本号或发布日期（任务已明确给出的除外）；不调整无关章节；不提交、不推送。
```

## 缺陷修复

```text
## 目标
修复空输入导致的异常，并保持非空输入的既有行为。
## 涉及文件
src/parser.py
tests/test_parser.py
## 具体做法
在 parse() 的入口处理空字符串；返回项目已有的空结果对象。
不改变其他解析规则。补充空输入的行为测试，保留现有测试。
## 验收
运行 python3 -m unittest discover -s tests -v。
报告修改文件、检查退出码、实际测试摘要、未解决问题。
## 禁止
不修改其他文件；不删减既有测试；不安装依赖；不提交、不推送。
```

此示例只有在项目确有这些文件、接口和命令时才适用；其他项目按真实结构替换。

## 批量精确替换

Codex 先审查替换内容与来源，再把执行计划交给 dsh。每批最多 5 个目标文件。

```text
## 目标
严格应用随任务提供的替换计划。
## 涉及文件
逐项列明不超过 5 个目标文件，以及只读的计划文件绝对路径。
## 具体做法
读取计划中每个文件的原文、替换文与预期匹配次数。
先检查全部目标路径都在 workdir 内、匹配次数全部符合计划，再写入。
任何前置条件不符都停止并报告，不自行模糊匹配或重新解释语义。
写入前保存本批可恢复的原文；报告实际修改文件与每项匹配次数。
## 验收
用计划规定的内容检查验证全部替换，并运行对应项目检查。
报告真实输出与退出码。
## 禁止
不改计划、不扩大目标范围、不重写整篇文档、不自动覆盖意外差异。
```

写入中断仍可能导致部分完成。重试前由 Codex 检查状态，不能直接重复执行整份替换。

## 失败后的返修

仅在拿到可信 session ID 时使用 dsh_resume。否则使用 dsh_run，并补齐当前文件状态与原方案。

```text
## 目标
只修复主代理独立复验发现的剩余错误。
## 涉及文件
逐项列明本轮允许修改的文件（不超过 5 个）。
## 具体做法
附主代理运行的准确命令、退出码、相关错误输出与期望行为。
说明哪些改动已验证正确、哪些是用户原有改动，要求保留。
## 验收
运行最小相关检查；通过后运行此前约定的整体检查。
报告命令、真实结果与仍未解决的问题。
## 禁止
不重复执行已经完成的迁移；不删除断言；不回滚用户原有改动。
```
